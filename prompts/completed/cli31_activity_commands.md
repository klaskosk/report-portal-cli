# PR 31: Activity Commands

## Goal

Add read-only `rp activity {get,list}` for project-scoped item activity.

## Context

Phase 7. The `ActivityScope` client already has `GetByID` and `ListForItem`. These are distinct from `activity-event` (PR 32) which is instance-scoped audit events. Activity here is project-scoped item activity logs.

### Client API surface

**ActivityScope** (via `client.Project(name).Activities()`):

| Method | Signature | Returns |
|--------|-----------|---------|
| `GetByID` | `GetByID(ctx, activityID int64)` | `*types.ActivityResource` |
| `ListForItem` | `ListForItem(ctx, itemID int64, ...ListActivitiesOption)` | `*types.PageActivityEventResource` |

Pagination options: `WithActivityPageNumber`, `WithActivityPageSize`, `WithActivitySort`.

### Relevant types

Look up in `pkg/types/`:
- `ActivityResource` — single activity record (has Id, User, ObjectType, ActionType, etc.)
- `PageActivityEventResource` — paginated page with Content slice and Page metadata

## Implementation plan

### 1. Create `internal/cli/activity.go`

#### `rp activity get <id>`

- One positional arg: numeric activity ID
- Project-scoped (needs `-p`/`--project`)
- Call `scope.Activities().GetByID(ctx, activityID)`
- Table output: format key fields from `ActivityResource` (ID, USER, OBJECT TYPE, ACTION TYPE, CREATED AT, etc.)
- JSON output: raw `ActivityResource`

#### `rp activity list --item <item-id>`

- No positional args
- Required flag: `--item` (int64) — the test item ID to list activities for
- Project-scoped (needs `-p`/`--project`)
- Pagination flags: `--page`, `--page-size`, `--sort`
- Call `scope.Activities().ListForItem(ctx, itemID, options...)`
- Table output: format each activity in the page (ID, USER, ACTION TYPE, CREATED AT, etc.)
- JSON output: raw page response

### 2. Register in root.go

Add `cmd.AddCommand(newActivityCmd())` in `newRootCmd()`.

### 3. Table formatting

Define `activityHeaders()` and `activityRow()` for table output. Key columns:
- ID
- USER (the user who performed the action)
- OBJECT TYPE
- ACTION TYPE
- CREATED AT (formatted timestamp)

## Test requirements

### Unit tests (`internal/cli/activity_test.go`)

- **Get:** requires exactly 1 positional arg (numeric ID)
- **List:** requires `--item` flag
- **Pagination:** verify page/page-size/sort flags exist on list
- **Command wiring:** verify `newActivityCmd()` has get and list subcommands
- **Project flag:** verify `-p`/`--project` is available

## Edge cases

- **Distinct from `activity-event`:** This is project-scoped item activity, not instance-scoped audit events. The `activity-event` command already exists and is separate.
- **List requires --item:** Unlike other list commands, this one requires the item ID because the API lists activities FOR a specific item.
- **Read-only:** No create/update/delete — activities are generated by the system.
- **ActivityResource fields are pointers:** Handle nil gracefully in table formatting.

## Example commands

```bash
# Get a specific activity
$ rp activity get 123 -p my_project
ID    USER    OBJECT TYPE  ACTION TYPE     CREATED AT
123   admin   testItem     updateItem      2024-01-15T10:30:00Z

# List activities for a test item
$ rp activity list --item 456 -p my_project
ID    USER    OBJECT TYPE  ACTION TYPE     CREATED AT
789   admin   testItem     updateItem      2024-01-15T10:30:00Z
790   john    testItem     linkIssue       2024-01-15T11:00:00Z
```
